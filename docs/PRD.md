# San9AutoDomestic 无感一键内政 PRD

- 文档版本：1.0
- 日期：2026-08-10
- 状态：冻结评审基线
- 产品代号：San9AutoDomestic Native
- 设计结论：`DESIGN-FEASIBLE`
- 当前实现结论：`IMPLEMENTATION-NO-GO`
- 取代文档：PRD 0.4 及此前所有以鼠标、键盘、坐标回放为执行手段的方案

> 本文定义最终产品行为与开发门槛，不授权立即向游戏进程写入、注入 DLL 或调用游戏函数。每一级 live 验证仍须按第 15 节单独取得用户授权。

## 1. 产品结论

开发一个独立的 Windows 小程序。用户照常启动自己的 `San9PKEasy.exe`、进入《三国志 IX 威力加强版》战略阶段并打开 `San9AutoDomestic.exe`，之后点击“基础内政”或“有钱内政”，程序即在后台处理全部直属城市。

正式执行层必须在游戏进程内、由经过认证的游戏主线程调用原生游戏逻辑。它不得移动或点击鼠标，不得模拟键盘，不得抢占游戏焦点，不得依赖截图、坐标、菜单、选人框或确认框。

“无感”在本产品中的准确含义是：

- 用户只操作助手窗口，不需要操作游戏内菜单。
- 游戏可以位于后台；批处理不得改变前台窗口和鼠标位置。
- 游戏不得弹出需要用户处理的城市菜单、选人框或确认框。
- 允许游戏因原生事务自然刷新数值、日志或非模态画面；不要求逐像素完全静止。
- 整个批次必须使用原生判定、原生候选、原生扣费和原生副作用；不能通过直接改数值伪装完成。

最终交付只有一个用户可见入口 `San9AutoDomestic.exe`。桥 DLL、配置和适配器可以作为程序目录内组件存在，但用户不需要单独启动任何诊断器、控制台或 DLL。

## 2. 产品目标

### 2.1 必须实现

1. 与用户日常使用的精确 `San9PKEasy 1.1.0.5 + Easy.dll` 共存。
2. 一次点击按所选方案处理全部直属城市；首版方案可编排五类已支持的内政命令。
3. 默认每条命令选择当前原生候选中的最优 5 人。
4. 同一武将在本旬成功执行一条命令后，不得被后续命令复用。
5. 灰项、已执行、达到上限、交战、混乱、委任、人数不足和资金不足均自动跳过。
6. 每条命令成功后重新读取游戏状态，再决定下一条命令。
7. 重复点击、双实例、迟到回执和超时不得产生第二次原生提交。
8. 执行过程可安全请求停止；不确定结果必须锁止执行直至游戏重启。
9. 方案增删、命令增删与顺序调整在已支持的五类命令内由配置完成，不依赖 `basic/wealthy` 代码分支。

### 2.2 明确不做

- 不再开发或发布鼠标、键盘、坐标、截图识别执行路线。
- 不把当前 `San9AutoDomestic.Input.Win32` 作为生产回退；它只能保留作历史研究或离线测试。
- 不修改 `San9PK.exe`、`San9PKEasy.exe` 或 `Easy.dll` 的磁盘文件。
- 不修改、替换、捆绑或再分发用户的 Easy 二进制；正式包只识别用户本机已有的精确文件。
- 不直接改存档。
- 不裸写商业、开垦、巡察、训练、修筑数值，也不裸写资金、命令位或武将行动位。
- 不自动推进旬。
- 不处理委任军团、港口、关隘、阵、部队、外交或战斗命令。
- 首版不支持其他 San9 版本、语言版本、未知汉化、San9PKHard、SanIX 或未知修改器。
- 不联网、不遥测、不上传存档或内存数据。

## 3. 精确支持环境

首个正式版本只支持以下同目录三件套：

| 文件 | 版本与结构 | 字节数 | SHA-256 |
|---|---|---:|---|
| `D:\三国志9\10101749\San9PK.exe` | x86；文件版本 `1.0.1.0` | 2,636,800 | `D20794AEFF67301EC2BF8C3BECB1E9944C68C6C0588FBFD4BF04E8597F0E5028` |
| `D:\三国志9\10101749\San9PKEasy.exe` | x86；文件版本 `1.1.0.5` | 24,576 | `CDACA1477EDB5A3BD79BDA8540E19837FC3F9170965D972E8E48FB24CAE21C07` |
| `D:\三国志9\10101749\Easy.dll` | x86；无导出 | 32,768 | `E8BA3A603F6B0E7AF8A246DA0FE5CBDBA86AD9B77C5A507DD86159EF6C74A3F0` |

游戏窗口类必须为 `KOEI_SAN9WINDOW`。一次批次必须绑定唯一游戏 PID、进程创建时间、主窗口 HWND、主线程 ID、主模块身份、唯一 San9PKEasy loader PID/创建时间、Easy Hook epoch 和实际加载的 Easy 模块身份。

支持顺序固定为：

1. 游戏启动。
2. Easy 完成注入。
3. 助手验证完整兼容档案。
4. 助手安装自己的桥并进入可执行状态。

如果助手先启动，只能等待或进行只读检测，不得抢先安装桥。发现同名错哈希、Easy EXE 正确但 DLL 错误、Easy 只完成部分 Hook、第二个修改器覆写任一锚点或存在第二个游戏实例时，必须在任何写入前拒绝执行。

`Easy.dll` 的运行基址不得假设恒为 `0x10000000`。所有兼容校验必须使用“实际模块基址 + 已冻结 RVA”。助手不得主动对 Easy 调用 `LoadLibrary`、`FreeLibrary` 或修改其引用计数。

## 5. 批处理规则

### 5.1 城市范围

- 批次开始时冻结全部玩家直属、可控且设施类型为“城市”的城市集合。
- 委任军团、港口、关隘、阵和其他设施不进入队列。
- V1 按游戏内部城市 ID 升序处理。
- 每座城市和每条命令开始前重新核验玩家、所属军团、直属控制、城市类型、场景代和进程代。
- 城市失控或变为委任时，跳过该城剩余命令；身份或代际不确定时停止整批。
- 城市绑定必须走经过验证的原生命令对象/目标语义。若无法闭合原生城市绑定，项目在该阶段硬 `NO-GO`，不得改回设施列表点击。

### 5.2 人员选择

- 正式执行以游戏原生候选过滤和排序为权威。
- 每条默认命令必须恰好选择 5 名当前可行动、属于该城且满足原生条件的武将。
- 候选少于 5 人时只跳过当前命令，不消耗任何武将。
- 同分时保留游戏原生在城候选顺序；不得用武将 ID 改变第五名裁决。
- 成功提交后必须重新生成下一条命令的候选，不能复用旧列表、旧 task 或旧指针。
- 只读预览可以显式显示静态能力代理，但生产执行不得把未验证的静态排序冒充 `native_best`。

### 5.3 资金与命令顺序

- 同一军团下多座城市共享军团资金；城市顺序会影响后续命令。
- 每条命令前重新读取军团资金并应用方案或任务保留金。
- 训练按原生零费用处理；其他四项按 5 人共 250 金处理，最终仍以原生校验和原生扣费为准。
- 灰项、已执行、达到上限、交战、混乱或资金不足只跳过当前命令，不能阻止后续原本可执行的命令。
- 不在不同命令之间做全局最优分配；严格按照配置顺序贪心执行。

## 6. 用户流程

1. 用户照常通过自己的 Easy 环境启动游戏并读取存档。
2. 用户停留在战略阶段；不需要打开任何城市菜单。
3. 用户启动 `San9AutoDomestic.exe`。
4. 助手显示以下之一：未发现游戏、版本不符、只读就绪、桥未启用、可执行、执行中、已停止、必须重启。
5. 每个新游戏进程第一次进入执行模式时，可以要求一次“启用本次游戏的无感执行”确认；桥准备完成后，方案按钮即为单击执行，不再弹出游戏内确认。
6. 用户点击“基础内政”或“有钱内政”。该点击同时构成本批次对冻结 PID/进程代和方案的明确授权。
7. 助手在后台显示城市、命令、已完成、已跳过和停止请求；游戏焦点与鼠标不变。
8. 完成后显示逐城汇总。用户回到游戏继续正常操作。

## 7. 外置窗口

主窗口必须常驻，且至少包含：

- 游戏、Easy 和桥的精确身份状态。
- 当前绑定的 PID、进程代和玩家势力摘要。
- 直属城市数量。
- “预览计划”按钮。
- 由配置动态生成的方案按钮。
- “请求停止”按钮，仅执行中可用。
- 当前城市、当前命令、成功数、跳过数和失败原因。
- 本轮结构化日志入口。
- 醒目的 `RestartRequired` 状态及恢复说明。

失败信息不得被普通检测日志淹没。任何未完成结果必须同时显示状态、错误码、具体消息和是否可能已经产生游戏副作用。

游戏未启动、游戏退出、连接失败或检测阻断都只能改变窗口状态，不得让主程序静默退出。第二次启动助手必须唤醒已有窗口。

## 8. 配置与扩展性

UI 根据版本化配置生成方案按钮；Core 将配置编译为不可变执行计划。生产代码不得按 `basic` 或 `wealthy` 写专用业务分支。

首版配置继续支持：

- `profiles`：1～20 个方案。
- `tasks`：每方案 1～20 条任务。
- `command`：`patrol | commerce | cultivate | train | repair`。
- `enabled`：启停方案或任务。
- `reserveMoney` / `reserveMoneyOverride`：`0..GAME_MONEY_MAX`。
- `cityScope=direct_cities`。
- `cityOrder=game_id_asc`。
- `selectionPolicy=native_best`。

默认发布方案只允许 `minOfficers=5`、`maxOfficers=5`、`requireExactCount=true`。配置模型可以保留 `1..5` 的未来值域，但生产执行遇到尚未验证的其他人数时必须明确报 `UnsupportedForExecution`，不得静默改成 5 人。

扩展规则：

- 在现有五类命令中增删、启停、重排任务，只改配置。
- 修改方案名称、保留金和城市顺序策略，只改配置及其合法值域。
- 新增第六类原生命令，必须增加版本锁定 descriptor、原生逆向证据、后置条件和验收；不能只写进 JSON。
- 原生事实映射必须使用穷举 registry；未知命令必须抛错，不能落入默认费用、能力或命令位。

## 9. 生产架构

### 9.1 组件

1. `San9AutoDomestic.UI`
   - 唯一可见入口、配置、授权、进度、停止与日志。
2. `San9AutoDomestic.Core`
   - 配置和值域、冻结计划、跳过规则、结果模型。
3. `San9AutoDomestic.Adapter.San9Pk101Easy1105`
   - 精确三件套档案、结构读取、Easy Hook 指纹、原生命令 descriptor 与后置快照。
4. `San9AutoDomestic.Broker`
   - 进程级单飞、序号、防重放、截止时间、持久 journal 与永久故障锁存。
5. `San9AutoDomestic.Helper32`
   - 最小权限加载和固定尺寸本机 IPC；不调用游戏业务。
6. `San9AutoDomestic.Bridge32`
   - 驻留游戏进程，在认证的主线程安全点推进一个有界原生 primitive。

UI/Core 不得包含游戏地址。Adapter/Bridge 不得读取用户配置来改变底层 ABI 或原生事实。

### 9.2 单一生产协议

正式实现只能保留一个经过 C# 与原生代码跨语言 golden vector 验证的 wire schema。现有 C# 288-byte 协议和 V5.x 256-byte ping 协议不能直接拼接或并存冒充生产协议。

该 schema 必须固定尺寸，明确小端序和逐字段 offset，并包含 schema 版本、声明长度、全零保留区、CRC32 损坏检测和 HMAC-SHA256 完整性校验。解码端必须用常数时间比较 MAC，并对未知 flag、非零保留位、截断、超长、CRC/MAC 错误全部 fail closed。IPC 对象必须使用当前用户受限 ACL；内嵌密钥和同用户 HMAC 不能被描述成抵抗同一用户恶意进程的信任边界。

生产请求必须绑定：

- 协议版本、BuildId 和三件套 profile digest。
- 游戏 PID/创建时间、Easy loader PID/创建时间、Easy Hook epoch、主线程 ID、HWND 和 session nonce。
- 严格递增 sequence、request ID、单调截止时间和上下文摘要。
- 城市 ID、军团 ID、命令 ID、按原生顺序冻结的 5 名武将。
- 请求指纹、阶段 ordinal、结果 ACK 和终态摘要。

wire format 不得包含任意原生指针、函数地址、代码、可变长度脚本或任意内存读写操作码。

## 10. Easy 共存契约

Easy 现有 Hook 永远归 Easy 所有。开发必须先产出完整 ownership manifest，至少记录每个写点的目标 VA/RVA、原始字节、Easy 安装后字节、实际跳转目标、Easy 函数 RVA 和已知用途。

当前静态分析已定位 32 个游戏代码重定向点和 6 个辅助物理写点。32 个重定向点具体由 1 个 5-byte JMP、29 个 5-byte CALL 和 2 个 6-byte CALL+NOP 组成；不能统称为 JMP Hook。6 个辅助写点包括 5 个游戏 VA `0x0040CAEF`、`0x0040BF25`、`0x0043DA06`、`0x0045AC96`、`0x004B06B1`，以及 Easy 实际模块基址加 RVA `0x6450` 的游戏 HWND 槽。现有主线程 idle 候选三锚与这些地址没有直接同址重叠，这只证明“设计上可能共存”，不等于已经兼容。

`0x0040CAEF` 与 `0x0040BF25` 属于“允许小兵培养”同一复选框路径，合法状态只允许成对的 `00/00` 或 `32/32`；单点合法而二者不一致仍必须阻断。该两态值必须进入批次 context digest，批次内改变则在 entered 前停止、entered 后 `AbortUncertain`。P0 还必须审计注入器全部 `WriteProcessMemory` 交叉引用来证明 manifest 完整；若发现新写点，先修订并重新冻结 PRD/manifest，不能带着开放计数进入 live。

P0 冲突图还要记录 Easy 对 `0x0061C000` 所在页的 `VirtualProtectEx` 保护属性转换。它不是额外物理写点，但可能影响同页 Hook/数据的所有权判断；新桥不得依赖 Easy 暂时留下的可写权限。

安装本工具桥之前必须连续两次稳定验证：

- 同一 PID 和创建时间。
- 唯一、精确的 Easy 模块和实际加载基址。
- 32 个代码重定向点按各自指令类型、长度和原始/安装后字节全部匹配，并指向该 Easy 模块的预期 RVA。
- 6 个辅助物理写点全部匹配各自的地址域、合法状态和来源；Easy 模块内 HWND 槽只按模块 RVA 解释，两个复选框写点必须成对一致。
- 本工具候选 idle slot、原函数和 caller 锚仍为预期值。
- 没有第三方补丁覆盖任何相关字节。

本工具不得覆盖、截断、恢复或改写 Easy-owned patch，也不得调用 Easy 内部函数作为稳定 API。Easy 内部函数是依赖寄存器、栈和硬编码续点的 trampoline，不是外部 ABI。

Easy GUI 在同一游戏进程期间被关闭、重新打开、卸钩或重钩都视为 Easy epoch 变化。本工具必须绑定 San9PKEasy loader PID/创建时间并记录 Hook epoch；桥安装后只要 loader 退出/换代、任一核心 Hook 曾缺失或观察到卸钩/重钩，本游戏进程代就永久进入 `RestartRequired`。即使随后同一 Easy.dll 基址上的全部指纹重新稳定，也不得在旧桥上重新放行。

发布前必须分别在以下三个时点回归 Easy 的“多人探索”和“军师推荐”：

1. 只有 Easy 的基线状态。
2. 本工具桥已安装但未执行内政。
3. 本工具完成一条原生内政后。

任何 Hook 指纹或 Easy 功能漂移都阻断发布。

## 11. 主线程与桥生命周期

- DLL 加载、IPC 和游戏业务严格分离。
- `DllMain`、loader 线程、外部线程、IPC 线程和 Windows HookProc 不得调用游戏业务函数。
- 业务 primitive 只能在已认证的游戏 UI 主线程安全点执行。
- 每次入口重新断言 TID、PID/进程代、scene/root generation、caller、app vptr、task/controller 和 Easy 指纹。
- 一次 idle 回调最多推进一个有界 primitive；不得 Sleep、等待 IPC、忙轮询或一次跑完整个城市循环。
- 原始 idle 函数必须在冻结的先后顺序下恰好调用一次，并保持栈、寄存器、FPU 和线程局部状态。
- 桥 slot 安装只能在游戏主线程用一次原子 CAS 完成：`exact_recorded_original -> our_wrapper`。CAS 失败必须零写入拒绝；不得在验证与安装之间用普通写入覆盖后来 owner。
- Stop 只在 primitive 之间生效，不能终止正在执行的游戏函数。
- 首版允许桥 pin 到游戏退出；在没有证明 callback quiescence、条件恢复 Hook 和安全卸载之前，不承诺关闭助手即可卸载 DLL。
- 当前恢复边界是重启游戏。

## 12. 原生命令事务

每条命令必须依次经过：

`FreshContext -> NativeCanExecute -> NativeCandidates -> NativeRank -> FreezeExactFive -> Construct -> Validate -> EnterOnce -> NativeApply -> NativeCleanup -> FreshPostSnapshotA/B -> Terminal`

硬规则：

- 所有玩法状态改变都来自原生事务。
- 不可逆入口前再次核验城市、军团、控制权、命令灰项、资金、候选、五人身份和上下文代。
- `EnterOnce` 使用进程内全局单飞和一次性 permit；Apply 最多一次。
- 成功必须由两次新鲜、稳定且有独立 read ticket 的后置快照证明。
- 后置至少核对项目值或训练状态、命令 order bit、五人行动占用和应有资金变化。
- 候选人数变化只能作辅助证据，不能替代上述字段。
- 已知业务条件失败且证明未进入副作用时，返回 `Skipped` 或 `RejectedBeforeMutation`。
- 一旦进入副作用，任何超时、异常、task 消失、部分后置、Easy 漂移、进程代变化或 IPC 丢失都必须返回 `AbortUncertain/HaltRestart`。
- `AbortUncertain` 后整批停止，不重试当前命令，不执行下一命令，不通过裸写补偿。

## 13. 停止、防重放与恢复

- 同一进程代只允许一个批次、一个未决命令和一个进入中的副作用。
- 方案双击、第二个助手实例、重复 nonce、重复 sequence、重复 request ID、过期请求和迟到回执都不得产生原生调用。
- 不可逆入口严格按 `Prepared durable -> one-shot permit -> Entered durable + flush success -> NativeApply` 排序。只有 `Entered` 已确认耐久落盘，才允许第一条 mutating primitive；任一落盘或 flush 失败都必须保持零 Apply。
- entered 与 terminal 状态必须单调、写穿并有校验。
- 启动时发现 Prepared/Entered 无 terminal、journal 损坏、Hook 所有权不确定或释放超时，必须保持 `RestartRequired`。
- UI 重启、助手重启或配置变化不能清除故障锁。
- 只有确认游戏 PID 创建代已经改变，才能解除该故障代的执行禁令。
- 若未来支持热卸载，slot 恢复只能使用原子 CAS `our_wrapper -> exact_recorded_original`；只有 CAS 成功、连续两个 idle epoch 无在途 callback 且 IPC 已封口时才允许卸载。CAS 失败或进入 COMMITTING 后发生超时/失联都必须保持 `RestartRequired`，不得用普通写入猜测恢复；否则继续 pin 到游戏退出。

## 14. 日志与隐私

每轮产生一个本地结构化日志，至少包含：

- 工具 BuildId、配置版本和三件套 profile digest。
- PID/创建代、玩家、直属城市冻结集合和计划摘要。
- 每城每命令的原生可执行结果、候选 ID 顺序、选中五人、费用和跳过原因。
- 每个 native primitive 的阶段 ordinal、耗时和终态，不记录任意函数参数原始指针。
- 前后快照摘要、Apply 计数、停止或 `AbortUncertain` 的最后安全点。
- Easy Hook manifest digest 及前后是否一致。

默认日志不得包含整块进程内存、存档内容、账号信息或无关文件。程序默认不联网。

## 15. 分阶段交付与授权

### P0：PRD 与静态兼容档案

- 冻结本文、三件套 manifest、Easy 32 个代码重定向点 + 6 个辅助物理写点的 ownership manifest 和冲突图；用全部 `WriteProcessMemory` 交叉引用审计证明计数完整。
- 将鼠标执行器从生产按钮和正式发布物中移除。
- 任一关键文件或锚点单字节变异都必须在零写入状态拒绝。

出口：静态审查通过。若找不到与 Easy 零冲突的主线程候选点，硬 `NO-GO`。

### P1：ping-only 主线程桥

- 使用复制环境并由用户另行授权安装独立桥。
- 协议不含城市、命令、武将或任意业务字段。
- 连续 100 次 ping 均在同一认证主线程安全点完成；游戏业务快照、前台 HWND 和鼠标位置不变。
- 任何失败后先重启游戏，不得自动进入下一试验。

出口：只证明主线程桥，不授权业务执行。

### P2：五类命令只读语义闭合

- 使用硬件执行/数据断点和只读观察取得 CanExecute、候选、排序、命令构造、Apply 与 cleanup 调用链。
- 五类命令已有不同 factory、handler、validator 和派生 Apply 的静态证据，因此巡察、商业、开垦、训练、修筑必须各完成至少一次独立人工原生轮次；商业和训练优先覆盖收费与零费用分支，但不能替代其余三类闭环。
- Bridge 只做 shadow，不进入 Apply。

出口：每类命令都必须有明确 ABI、对象所有权和后置条件；缺一项则该命令 `NO-GO`。

### P3：单城单命令

- 只开放一个直属城市的一次商业请求，使用专用复制存档和一次性 nonce。
- 后台无感完成，Apply 计数恰好 1。
- 商业值、order bit、五人行动位和军团资金全部满足原生后置。
- 保存、重载和推进一旬后与人工原生行为一致。
- 各阶段故障注入：entered 前安全拒绝，entered 后锁存重启。

出口：单城商业原生事务通过独立复审。

### P4：单城五类命令

- 逐项开放巡察、开垦、训练和修筑，再验证两个默认方案。
- 每类至少覆盖可执行、灰项、人数不足、资金不足或训练零费用、已执行。
- 每条命令重新取候选，后续不复用已行动武将。

出口：五类命令均与人工原生结果一致，生产输入模拟调用为 0。

### P5：全部直属城市

- 冻结直属城市集合，逐城逐命令重新验证控制权和上下文。
- 只使用已经闭合的原生城市绑定或直接命令对象语义。
- 验证共享军团资金、跨城顺序、灰项继续、失控/委任跳过、停止和重复点击。

出口：完整 Basic/Wealthy 各跑 20 轮，无重复 Apply、无崩溃、无坏档。

### P6：Easy 共存与正式发布

- 完成 Easy 基线、装桥后、内政后三级“多人探索/军师推荐”回归。
- 覆盖 Easy GUI 在同一游戏进程中关闭、重开、卸钩和重钩；任何 Easy epoch 改变都必须停止并要求游戏重启。
- 完成错误版本、部分 Hook、第三方覆盖、断 IPC、游戏退出、助手退出和故障恢复测试。
- 通过离线测试、PE 能力审计、Hook ownership 审计、实机故障注入和独立复审。

出口：只有本阶段通过后，正式发布物才可把方案按钮标记为“无感执行可用”。

静态分析、只读 live、ping-only、no-op safe-point、单命令、Easy 回归和多城执行属于不同授权级别。前一级成功不自动授权后一级。

## 16. 核心验收矩阵

1. BASIC，10 名候选且资金充足：商业原生最优 5 人；开垦使用剩余原生最优 5 人。
2. BASIC，7 名候选：商业 5 人；开垦因不足 5 人零 Apply 跳过。
3. 商业灰色：商业零 Apply；开垦仍可使用 5 人。
4. Wealthy，20 名候选：前四项执行，第五项因人员不足跳过。
5. 中间命令灰色：不消耗候选，后续命令继续。
6. 资金不足 250：四项收费命令跳过；训练仍按零费用原生判定。
7. 设置保留金：任何会使原生预计余额低于保留金的命令跳过。
8. 直属城与委任城并存：仅直属城可能进入 Apply。
9. 城市、港口和关隘并存：仅城市进入队列。
10. 队列形成后城市失控：该城剩余命令零 Apply。
11. 前一命令成功：其五人不出现在后一命令可执行五人中。
12. 方案双击、双助手实例和重复 IPC 请求：Apply 总数不增加。
13. 游戏位于后台：前台 HWND、鼠标位置和键盘状态不变，游戏无选人/确认菜单。
14. 错误 EXE、错误 Easy、部分 Hook、未知模块或关键字节变化：在桥写入前拒绝。
15. 进入 Apply 前停止：安全停止；进入 Apply 后丢回执：`RestartRequired`，绝不重试。
16. 单条命令成功后保存/重载：业务值、资金和行动结果与人工原生命令一致。
17. 推进下一旬：只复位游戏本应复位的 order/行动字段，不出现额外扣费。
18. Easy“多人探索”和“军师推荐”在装桥前后与内政后保持一致。
19. 执行期间关闭助手：不终止游戏线程；桥保持安全驻留，状态按 journal 恢复或要求重启。
20. 生产二进制静态扫描：本工具的业务执行路径不导入或调用 `SendInput`、`mouse_event`、`keybd_event`，不发送鼠标/键盘消息，也不存在隐藏回退路线。

## 17. 完成定义

只有同时满足以下条件，Goal 才可标记完成：

- 本 PRD 与最终行为一致，所有变更经过明确评审。
- 一个用户可见 EXE 完成检测、预览、授权、执行、停止和汇总。
- 现有鼠标执行路线不再能从正式 UI 或生产配置触达。
- 精确 Easy profile、32 个代码重定向点 + 6 个辅助物理写点指纹和新桥 ownership 全部通过。
- 原生主线程桥、五类命令和原生城市绑定均有动态证据。
- 两个默认方案由配置生成并跑完全部直属城市。
- 核心验收矩阵全部通过；Easy 两项功能回归通过。
- 复制存档完成提交、重载和下一旬验证，无崩溃、坏档或重复命令。
- 交付程序、默认配置、Hook manifest、使用说明、测试报告、已知限制和恢复说明。
- 独立审查未发现未关闭的 P1/P2；任何剩余硬阻断明确标记 `NO-GO`，不以鼠标方案替代。

- `San9WPK.CT` 只作为跨版本 AOB 和结构假设来源；其完整签名已有 3 条在目标 EXE 中唯一命中，但没有原生内政提交链。因其 GPL-3.0，正式实现采用独立重建，不直接复制其脚本代码。
- `kaodata` 的 San9 内容仅覆盖头像/色盘 `.s9` 资源，不作为运行时城市、武将或命令格式依据。
- PS2 PNACH 只用于字段相对布局的二级旁证；PS2 地址、MIPS 代码和无明确许可的补丁内容不得进入 PC 产品。

- 与 Easy 共存的生产桥安装与安全生命周期。

- 五类内政的完整原生 ABI、主线程 Apply 与 cleanup 动态闭环。
